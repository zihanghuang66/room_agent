# VGGT-Ω 试验包 v0.3.0

当前：首轮 50 帧真实推理已通过，RTX 3090 上前向约 7.32 秒、峰值已分配显存约 8.07 GiB，得到可辨认室内点云。根据用户要求，v0.3.0 改为每秒 2 帧：沿用排除前 5 秒开门片段的范围，5.00–54.50 秒共 100 帧。模型、权重、512 最长边和原环境保持不变。100 帧 GPU 推理尚未实测，显存不足会报错并返回日志，不会悄悄减少帧数。

## 上传、解压、运行

只需上传 `room-vggt-omega-v0.3.0.tar.gz` 到 `/yinxin/projects/room/scripts/`。启动脚本已经包含在压缩包内，不需要额外下载任何 `.sh` 文件。

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-vggt-omega-v0.3.0.tar.gz
bash /yinxin/projects/room/scripts/vggt-omega/run_room.sh
```

如果已解压，只运行最后一条命令即可。它正式启动每秒 2 帧、共 100 帧的重建，默认使用 `/yinxin/projects/room/model/vggt_omega_1b_512.pt`。不会自动安装环境、下载权重或重跑全部历史任务。旧版上传包、venv 和既有结果保留；解压更新当前 `scripts/vggt-omega` 中的脚本。包外的旧启动脚本不再使用。

完成或失败后，把终端 `RETURN ARCHIVE` 指向的准确压缩包返回。重建返回包在 `/yinxin/projects/room/return_output/room_omega_*.tar.gz`。运行中日志路径会显示在终端。

## 同一个脚本的其他操作

只检查输入、依赖、GPU 和官方图像预处理，不做重建：

```bash
bash /yinxin/projects/room/scripts/vggt-omega/run_room.sh check
```

这一步返回 `return_output/room_omega_preflight_*.tar.gz`。预检只判断权重文件存在，不加载它：`ready_for_weight_loading_test` 不代表权重有效或推理通过。环境/输入错误为 `needs_attention`；缺权重为 `ready_without_weights`。缺少权重不影响其余独立检查。

只有更换容器后环境确实丢失或损坏，才使用安装操作：

```bash
bash /yinxin/projects/room/scripts/vggt-omega/run_room.sh install
```

仅检查 100 帧哈希、无需 GPU：

```bash
bash /yinxin/projects/room/scripts/vggt-omega/run_room.sh inputs
```

`environment_reference.json` 保存学校已安装的包版本；核心 torch / torchvision / numpy / vggt-omega 变化会使预检失败，其他变化记录在 runtime.json 中。它不是离线安装包。

默认推理超时 1800 秒，超时会终止本脚本启动的进程并返回已有日志。显存不足会报错，不静默减少输入。使用容器内逻辑 GPU 0，保留学校的 CUDA_VISIBLE_DEVICES。脚本支持 ROOM_PROJECT_ROOT、ROOM_CHECKPOINT、ROOM_PYTHON 环境变量供路径迁移；默认值已对应当前学校环境，正常使用无需设置。

## 本轮抽帧与对照

复用服务器已有每秒 4 帧的图像目录：

```text
/yinxin/projects/room/return_output/artifacts/room_sparse_20261030T081153Z_tu6c0636/frames
```

从 `frame_000021.jpg` 开始隔一张取一张，直到 `frame_000219.jpg`，得到 100 张图像，时间为 5.00、5.50、6.00……54.50 秒，间隔严格为 0.5 秒。这里复用已经解码的 4 fps 图像，不重新解压 MOV 或重新转码。具体文件、时间和 SHA256 见 input_manifest.json。前 5 秒开门片段继续排除，保证与上一轮的场景范围接近。

旧 50 帧的均匀采样落在不同时间网格上，本轮严格 2 fps 与它共享 25 张图，**不是完整包含旧 50 帧的扩展集**。旧返回包与 v0.2.2 上传包保留。后续将对比共同视角、相同时间区域及转场一致性；不能声称只改变帧数而所有图像身份都保持不变。

一次联合推理全部 100 帧，预期输入形状 `[100,3,512,288]`。使用同一个 `vggt_omega_1b_512.pt` 与 `max_size` 预处理、最长边 512。现有 900×1600 图像变为 288×512。输入验证、预检、推理和输出检查都依据清单帧数，不再写死 50。

更多帧可能补充过门口和转身时的中间视角，但不能保证改善反光、动态人物或纹理缺失。上一轮相同 50 帧的 COLMAP 失败结果不是本轮 100 帧传统基线，不能直接用于算法优劣结论。

如需指定迁移后的图像目录，入口仍支持 `--frames-dir`，但全部文件哈希必须与清单一致。正常使用不需要修改命令。

## 输出与查看

所有新增报告、缓存、运行产物和返回包在 `return_output/`。用户已下载的权重沿用 `model/` 路径。每次运行新建 `return_output/artifacts/room_omega_时间_随机串/`，不覆盖旧结果。

| 文件 | 内容 |
| --- | --- |
| `room_cloud.ply` | 彩色点云，XYZ/RGB/原始置信度。VS Code PLY 插件或 CloudCompare 可查看 |
| `preview.png` | 点云和相机轨迹的两个投影，不裁掉远处点 |
| `depth_preview.png` | 6 个代表帧的 RGB 与预测深度，显示色阶截到 2/98 分位 |
| `predictions.npz` | 全部 100 帧未经置信度筛选的深度、置信度、内外参、处理后 RGB |
| `cameras.json` | OpenCV 世界到相机外参、内参、相机中心和帧名 |
| `metrics.json` | 推理时间、GPU 显存峰值、有效深度数量和点云筛选统计 |
| `result.json` / `inference.log` | 成败状态与错误；缺权重时不启动推理 |

本轮导出点数上限仍为 50 万，以保持查看和传输成本可控；即使点数上限相同，模型已经联合使用 100 帧，NPZ 保留全部原始预测。

PLY 只保留有限正深度、有限置信度，按所有有效像素的置信度第 50 分位筛选，再用固定随机种子抽样最多 50 万点。原始预测仍在 NPZ 中，筛选不等于几何正确。置信度不是概率；尺度未通过实物尺寸标定。输出是点云，不是完整 Mesh、家具分离或 USD。

返回包包含处理后 RGB，因而会包含房间影像；不包含权重、原视频或整个 Python 环境。完整点云和原始预测可能使返回包达到数十至数百 MB，具体以实际大小为准。

## 环境、成本与复用

脚本针对已有报告中的 Linux x86_64、`/usr/bin/python3` Python 3.10。每次 setup 新建 `.venvs/room_omega_setup_.../`，不修改系统 Python 或现有 COLMAP 环境。沿用根目录现有 `.venvs` 约定；源码在 `scripts/vendor/`；安装构建目录、下载及 pip 缓存全在 `return_output/`。安装成功才更新 `return_output/environments/omega-current.json`。

核心版本固定为 PyTorch 2.6.0 / torchvision 0.21.0 / CUDA 12.4 wheel，其他直接依赖见 requirements.txt；间接依赖安装后记录在 `pip_freeze.log`，这还不是完整离线环境锁文件或 Docker image。下载需要访问 GitHub、PyPI 和 PyTorch wheel 服务器，网络流量和环境占用均为数 GB 量级；权重另计。动态 GPU 型号变化时记录实际设备和显存，不将官方 A100 指标当成本次测量。

如果新容器保留 `/yinxin/projects/room` 且 Python 基础环境兼容，可先尝试已有环境；基础镜像变化、环境丢失或导入失败时重新运行 setup。持久化目录本身不能保证换基础镜像后 venv 仍可用。此包不构建 Docker image，先根据返回报告确认这套依赖可运行。
