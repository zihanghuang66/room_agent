## v0.1.1 修复

v0.1.0 把提示词紧接在可变长 `--image` 参数后，CLI 会把提示词当作图片参数，进而报告 stdin 没有提示词。v0.1.1 使用 `--` 明确结束选项，再传提示词。已用本机真实 CLI 复现旧参数问题，回归测试也能使旧适配器失败、新适配器通过。

新版保留具体失败阶段、CLI 退出码、脱敏后的 stderr 和异常链，避免只返回 RuntimeError。这个修复不重新登录、不读取登录文件、不更换模型。生成新版本隔离源码目录，保留原来的 v0.1.0。

之前文本测试通过不等于图片与 MCP 适配通过；本地离线测试也不等于服务器真实调用通过。

## 替换范围

- 原来直接调用 Claude 的物体分类、椅子分组、布局合并判断、布局修正和完整性检查，改用 Codex CLI；视觉调用显式附带图片。
- 房间编辑、材质、质量检查、物体生成和物体细化统一选择现有 Codex 后端；工具通过 stdio MCP 提供。
- 禁止回退到 Claude。结构化分类和完整性判断验证 JSON Schema，检查失败不冒充检查通过。
- 使用学校服务器此前已验证可用的 `gpt-6-astra`，并发为 1。会消耗 Codex 账号额度；不能从该 CLI 获得金额估算。

这不是“全部依赖只剩 Codex”：Blender、几何算法、GPU 生成模型和图像生成 API 仍是独立依赖。本包不把 Codex 登录转换为 OpenAI/Gemini 图像 API 权限，也不保证替换后的结果与 Claude 相同。

复用已验证的 Python 环境，不卸载旧的 `anthropic`/`claude-agent-sdk` 包，不修改原始依赖锁文件。它们可以留在环境中，但适配后的 Python 执行路径不导入或调用 Claude SDK。`.claude/skills` 保留原名，因为其中是需要复用的建模说明和辅助脚本；目录名不表示运行 Claude。上游旧说明中的 Claude 使用方式不适用于这个分支。

## 上传、解压、运行

把 `room-litereality-codex-v0.1.1.tar.gz` 上传到 `/yinxin/projects/room/scripts/`，然后完整执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-litereality-codex-v0.1.1.tar.gz
bash /yinxin/projects/room/scripts/litereality-codex/run_room.sh
```

启动脚本会依次：

1. 校验原始源码 SHA256，生成 `scripts/vendor/litereality-agent-28ffe1f-room-codex-v0.1.1/`。
2. 运行离线测试和 CLI 导入检查。
3. 发起一次真实 Codex 看图分类请求，校验 JSON 答案。
4. 发起一次真实 Codex MCP 请求，调用测试工具并写出测试文件，验证返回内容。
5. 无论测试通过或失败，尽可能将报告打包到 `return_output/room_litereality_codex_时间_编号.tar.gz`，终端打印完整路径。

将终端打印的压缩包发回检查。测试不需要 GPU 或 Blender；通过只表示适配接口的基础能力可用，完整 room_002 重建仍需后续验证。

报告和测试文件放在 `return_output/artifacts/`。回传包只包含报告、测试日志、补丁清单和哈希清单，不包含账号配置、登录文件或原始扫描。归档时间固定为 0，避免未来时间警告。

## 复用与恢复

新终端需要启用此版本时：

```bash
source /yinxin/projects/room/scripts/litereality-codex/activate_room.sh
```

它设置 Python 源码搜索路径和 Codex 角色配置，不运行重建。原版源码仍在原目录；在新的、不加载上述脚本的终端可继续使用原流程。不要在同一进程内混用两个版本。

本包不是 Docker 镜像。容器重建后项目内源码仍会保留；Python 环境能否直接复用取决于新镜像的 Python、系统库和驱动兼容性。Codex CLI 或登录若存放在不持久化的 HOME 中，需要恢复安装或重新登录。

开发验证可追加 `--offline-only`，此时不请求 Codex；`--app-python /完整路径/bin/python` 可指定既有环境。不要将离线检查通过解读为真实模型调用通过。
