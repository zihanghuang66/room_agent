# room_002 无图像 API 基线 v0.1.0

运行范围：原始扫描检查 → 固定 LiteReality 提取器解析 → 全帧 RGB-D 点云融合 → TSDF 初版 Mesh → 原始 RoomPlan 布局和观测 Mesh 的 Blender/GLB 导出 → CPU 预览图 → 文件重新加载验证。

不调用 Codex/Claude/图像生成 API，不下载任何模型，不安装或覆盖环境。这是 LiteReality 的离线输入与几何基线，不是官方完整 ingest/seed/author 流程。原始 RoomPlan 的家具几何主要是代理形状，不能称为精细家具重建或观测 Mesh 的家具分离。

## 学校运行

使用已准备的 LiteReality 镜像，默认 Python `/opt/room/envs/app/bin/python`，Blender `/opt/room/bin/blender`。
输入：`/yinxin/projects/room/data/raw/room_002/LiteReality-LiteReality_Scanner-Studio_9952-20261031-090455.tar`。

把 `room-litereality-noapi-v0.1.0.tar.gz` 上传到 `/yinxin/projects/room/scripts/`，运行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-litereality-noapi-v0.1.0.tar.gz
bash litereality-noapi/run_room_002.sh
```

整个过程不需要密钥。可以在 tmux 会话中运行，以便 SSH 断开后继续计算。当前流程用 CPU，GPU 环境和模型推理不是本次验收项。

## 返回什么

结束时打印 `RETURN_TAR`；将它对应的 `return_output/room_002_noapi_时间_编号.tar.gz` 回传。

归档中的 deliverables/：

- observed_cloud.ply：所有帧投影并体素合并后的彩色点云。
- observed_mesh.ply / observed.glb / observed.blend：深度融合得到的连续表面；不是生成式补洞，可能有缺口或漂移。
- layout.glb / layout.blend：原始 RoomPlan 墙体、家具代理形状，保留独立对象，用于布局核对。
- cloud_views.png：点云顶视、正视、侧视。
- layout_overview.png / layout_top.png、observed_overview.png / observed_top.png：Blender Cycles CPU 预览。
- geometry_summary.json、fusion_frames.json、两个 *_export.json、reopen_verification.json：几何、单位、参数和重新加载检查。

根目录还含 RGB 联系表、逐帧检查、结果与日志。观测 Mesh 与代理布局分别导出，避免重复叠放造成误解。

全部新增文件位于 return_output/。原始 tar 保留不修改。回传包不含扫描解包副本、离线提取的大量中间帧、账号配置或登录数据。首次运行会在本次 artifacts/work 下解包，离线提取会再复制帧，建议为输入及产物预留数倍于扫描包大小的空间。

## 参数与尺度

每一帧都处理（frame_stride=1），不设固定帧数和点数截断。默认置信度>=1（存在 confidence 图时）、深度 0.15–6 米；点云体素 1 厘米、TSDF 体素 2 厘米。置信度文件缺失会被逐帧记录。空间合并会降低重复观测密度，不代表所有像素都保留成独立点。

毫米深度转米，使用扫描器 ARKit 位姿。PLY 为 ARKit Y-up；Blender 转换为 Z-up，GLB 按 glTF 约定导出。尺度沿用设备测量，未通过实测尺独立标定。两个 GLB 重新加载后验证包围范围和网格数量。

可选更细（内存与运行时间增加）：

```bash
bash litereality-noapi/run_room_002.sh --voxel 0.01
```

默认同一输入 SHA、脚本内容和参数使用同一个运行目录，逐阶段核对输出哈希后复用。失败阶段再次执行，已有成功阶段保留。重新运行同一条命令即可续跑。需要全新一轮时加 `--fresh`。不支持同时对同一个运行目录启动两份任务。

## 错误和验收

终端显示每步 PASS/FAIL/REUSED 和关键错误，详细日志随返回包保留。失败后继续运行不依赖失败阶段的导出；有失败则最终非零退出。

只有 `RESULT offline_baseline_passed` 表示本次离线基线通过；这也不意味着重建质量合格或完整 LiteReality 成功，还要人工核对尺度、覆盖和视觉结果。`geometry_only_blender_not_validated` 是诊断状态，不能当完整验收通过。

如果镜像的路径不同，可设置 ROOM_PYTHON / ROOM_BLENDER / ROOM_LITEREALITY_SOURCE，不需要修改源码。缺失 Python 时启动器尝试系统 Python 生成失败报告。输入超过 2 GiB（解包后）会明确停止，不会静默截断；若出现此提示应调整资源限制后重跑。
