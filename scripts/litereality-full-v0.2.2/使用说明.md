# room_003/test_03 全量测试 v0.2.2（轻量包）

默认输入：`/yinxin/projects/room/data/raw/room_003/test_03.tar`。
场景名称：`room_003_test_03`。不读取或修改 room_001/test_01、room_002 的场景结果；仅复用已安装环境和模型权重缓存。

上传到 `/yinxin/projects/room/scripts`，前台执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-litereality-full-v0.2.2.tar.gz
bash room-litereality-full-v0.2.2/run_test_03.sh
```

用户自行管理 tmux，启动脚本没有后台或 tmux 逻辑。

## 流程

输入 SHA256 与全部 RGB/深度/相机 JSON 文件配对检查 → 已安装 Codex/MCP 实际命令验证 → GPU 算子、Blender CPU/EEVEE 和模型加载 → ingest（提取、柜体合并、布局验证、视角选择、内置 imagegen 参考图）→ reconstruct（家具三维生成）→ seed（组装与相机核对）→ author（场景细化、材质与质量检查）→ publish → 贴图打包和 BLEND/GLB 重开检查。

“全量”表示完整流程，不意味着每帧都调用生成模型。照片由上游规则选择，视觉验收当前使用 6 个视角。家具数量来自本次扫描，没有人工确认的数量，不套用旧场景修正。布局与质量验收仍保留，不能承诺新数据一定通过。

## 环境

使用已准备好的 Linux x86_64 LiteReality 容器、已登录且启用内置 image_generation 的 Codex、已分配的 NVIDIA GPU。复用 ROOM_CODEX 或当前 PATH 的 Codex，不包含、下载或安装 Codex 运行时，也不修改登录。默认应用 Python 为 `/opt/room/envs/app/bin/python`，GPU Python 为 `/opt/room/envs/gpu/bin/python`，Blender 为 `/opt/room/tools/blender/blender`。

尊重 CUDA_VISIBLE_DEVICES，使用可见 cuda:0；预检要求至少 18 GiB 可用显存。初始 TRELLIS 分辨率 512。会消耗 Codex/内置图像生成额度和 GPU 时间；默认参考图生成会话上限 64，修模最多 2 轮，每轮 40 次工具调用/600 秒。

## 输出与失败处理

所有运行输出均在 `/yinxin/projects/room/return_output`：

- 工作目录：`artifacts/room_003_test_03_full_v0.2.2_<输入与配置哈希>/`。
- 返回包：`room_003_test_03_full_<UTC时间>_<随机后缀>.tar.gz`。
- 总状态：工作目录内 result.json；阶段状态：stage_*.json 与 scenes/room_003_test_03/.litereality/pipeline.json。
- 成功发布的模型：scenes/room_003_test_03/realism_authoring/room_preview/Room.portable.blend、Room.glb；应同时确认 full_run_completed=true。
- author/publish/重开失败且已有 authored Room.py 时，会尝试导出 candidate_preview/Room.portable.blend、Room.glb；候选不等于通过验收，查看 candidate_status.json。

错误同时打印终端和保存日志，普通异常/超时/SIGTERM 会尝试生成返回包。SIGKILL、容器回收、磁盘耗尽不能保证打包完成。

本版修正报告收集：保留内部 object_init/input/scene_data 的布局 JSON、合并记录、参考图和 pickle 数据（仅按字节打包，不读取执行）。顶层原始扫描、内部 RGBD 副本、模型缓存、认证文件和符号链接目标不打包。无需再为布局失败单独补收集。

同一输入和配置重复运行会复用有效阶段。原始 tar 内容改变会使用独立目录。失败 author 重跑可能重新执行编辑阶段，报错后先回传，不盲目重试。原始数据解压上限 32 GiB。
