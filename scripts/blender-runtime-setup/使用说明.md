# Blender 持久化安装与渲染测试 v0.1.1

用途：为 Room 项目准备官方 Blender 5.1.2 Linux x86_64，实际执行小场景渲染和 GLB 导出。
当前仅 Codex 文本模型访问已验证；本包不调用 Claude、Codex 或图像生成 API，不启动完整 LiteReality。

推荐离线安装：把新版脚本包和官方 `blender-5.1.2-linux-x64.tar.xz` 一起上传到 `/yinxin/projects/room/scripts/`，无需解压官方 tar.xz。启动脚本会自动识别它、校验 SHA256，然后直接安装，不访问下载站。

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-blender-runtime-setup-v0.1.1.tar.gz
bash /yinxin/projects/room/scripts/blender-runtime-setup/run_room.sh
```

脚本依次：
1. 修正本次进程的 Codex PATH，检查工具和 CUDA 编译器位置。
2. 优先使用 scripts/ 中上传的官方 tar.xz（也可用 `--archive /完整路径/文件.tar.xz` 指定）；否则使用已有缓存或从官方站下载。核验固定 SHA256 后安装到持久化目录。
3. 创建简单立方体，测试 Cycles CPU 渲染并导出 test_cube.glb / test_cube.blend。
4. 分别执行 Cycles CUDA 与 EEVEE 渲染，单项失败仍保留其他项结果。
5. 将日志、测试图片、测试模型和环境摘要打包到 return_output。

测试立方体不是 room_002 重建结果。此包不会读取或修改扫描。

## 持久化路径

- 程序：return_output/tools/blender-5.1.2-linux-x64/
- 安装信息：return_output/tools/blender-current.json
- 下载缓存：return_output/cache/blender/
- 每次结果：return_output/artifacts/room_blender_setup_<时间>_<编号>/
- 返回包：return_output/room_blender_setup_<时间>_<编号>.tar.gz

重建容器后，在当前终端恢复本包提供的工具路径：

```bash
source /yinxin/projects/room/scripts/blender-runtime-setup/activate_room.sh
```

这只设置 Blender/Codex 的程序路径，不迁移或恢复 Codex 登录凭据。
共享目录保留不代表新容器的系统库兼容；本包可重跑验证。

## 条件与限制

- Linux x86_64、Python 3.10+、至少 5 GiB 可用空间；未提供安装包时才需要访问 download.blender.org。
- 无需 sudo，不安装或更改 NVIDIA 驱动，不创建嵌套 Docker。
- 如启动失败，报告会保留系统动态库错误；不自动 apt 安装。
- nvidia-smi 成功不代表 nvcc 存在。模型 CUDA 扩展编译与 Blender GPU 渲染是不同检查。
- TRELLIS_PYTHON、GROUNDING_DINO_PYTHON 仅检查配置的解释器是否存在，不代表模型已加载。
- API 只记录环境变量是否存在，不读取 CLI 登录缓存、不发送密钥、不调用收费模型。
- 下载失败记录阶段、尝试次数、异常类型和 HTTP 状态码；不记录原始错误正文、代理地址或请求头。对 408/429/500/502/503/504 和连接超时最多尝试三次；403/404 等不盲目重试。
- 使用明确 User-Agent；这不能保证绕过学校网络限制，因此提供离线安装方式。
- tar/gzip 时间戳均为 0。
