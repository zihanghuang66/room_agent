# Codex DNS 临时修复 v0.1.0

适用：room_codex_network_20261103T140805Z_8ec8ad21 的诊断结果。
系统解析器 100.92.0.3 将 chatgpt.com 返回为 104.244.46.57，连接超时；Google HTTPS DNS 返回的 104.18.32.47、172.64.155.209 均能完成域名证书验证并收到 HTTP 403。
已定位当前解析路径给出了不可达地址；不能仅凭此确定 DNS 污染来源，也不能排除修复后仍存在 HTTP/账户层限制。

## 运行

上传压缩包至 /yinxin/projects/room/scripts，在学校容器以 root 前台执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-codex-dns-repair-v0.1.0.tar.gz
bash room-codex-dns-repair-v0.1.0/repair.sh
```

看到 DNS_TRANSPORT_OK 后启动一个新的 Codex 进程：

```bash
bash /yinxin/projects/room/scripts/room-codex-dns-repair-v0.1.0/start_codex.sh
```

启动脚本使用 codex --no-daemon，避免旧后台进程保留解析状态；不杀死任何已有任务。进入后发送一条简单消息确认真实请求正常，再退出并续跑重建。无需重新登录。
HTTP 403 只表示收到 HTTP 响应，不表示 Codex 可用。若工作区路由仍报错，回传新错误及 repair 输出；不要反复安装、登录或盲目修改更多域名。

## 修改范围与恢复

- 通过 Google DNS-over-HTTPS 动态查询当前 IPv4，不硬编码今天的 chatgpt.com 地址。
- 查询和目标连接都保留 TLS 证书验证；不使用 -k。
- 仅更新当前容器 /etc/hosts 中的 chatgpt.com，保留其他主机映射。
- 不修改 /etc/resolv.conf、Codex 配置或登录；不安装任何软件、不调用模型。
- 若目前设置了代理环境变量，与本次诊断条件不一致，停止而不改 hosts。
- 修改前备份到 return_output/environment_reports/room_codex_dns_fix_<时间随机>/hosts.before。
- 使用原文件写入方式兼容容器 bind mount；如果 hosts 只读或平台拒绝写入，会停止并输出错误。
- 修改后的普通 HTTPS 请求验证失败会自动恢复；平台在其间修改过 hosts 时拒绝覆盖，并明确报告。
- 终端打印 BACKUP_DIR、精确的回滚命令及 RETURN_TAR。返回 tar 只含报告，不含整个 hosts 或认证文件。

手动恢复使用脚本打印的实际备份路径：
`bash repair.sh --rollback /yinxin/projects/room/return_output/environment_reports/room_codex_dns_fix_<实际时间随机>`。
如果修复后还有其他 hosts 变更，自动回滚会拒绝覆盖，需要按报告核对，防止丢失后续配置。

## 为什么旧容器能用，新容器不能用

相同镜像不保证相同 DNS、宿主节点、出口、解析缓存或临时代理设置。容器平台可在启动时注入 hosts/resolv.conf。
没有旧容器当时的解析快照，无法认定具体变化。本次对照已足够先处理 chatgpt.com 解析路径。

此方案是临时覆盖，hosts 不遵守 DNS TTL。IP 后续会变化；容器重建后映射可能丢失。持久化项目里的脚本可重新运行以获取当前地址，但不要把固定 IP 当成永久镜像配置。
长期修复应由学校平台维护者检查 100.92.0.3 及其上游 DNS，或提供稳定合规的 DNS/网络出口配置。
不建议未经测试把全局 DNS 改为 8.8.8.8：本次只验证了其 HTTPS DNS 接口，未验证普通 UDP/TCP 53，也不能破坏学校内部域名解析。
