# 重建诊断采集包 v0.1.0

当前两次重建的最大模型均只覆盖开头约 5 秒。本包收集现有数据供本地检查，不运行新重建、不使用 GPU、不安装依赖，不修改已有模型或数据库内容。使用系统 Python 3.10 即可。

先确认目标重建任务已结束。上传 `room-reconstruction-diagnostics-v0.1.0.tar.gz` 到 `/yinxin/projects/room/scripts/`，执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-reconstruction-diagnostics-v0.1.0.tar.gz
/usr/bin/python3 /yinxin/projects/room/scripts/reconstruction-diagnostics/collect.py \
  --run-dir /yinxin/projects/room/return_output/artifacts/room_sparse_20261030T081153Z_tu6c0636
```

终端显示 `Return this archive:` 后，将对应 `room_diagnostics_*.tar.gz` 回传。请传新生成的诊断包，不是此前的 `room_sparse_*.tar.gz`。

## 包含什么

- 该次运行的全部抽帧 JPEG，保留原分辨率与颜色。
- `database.db` 的 SQLite 一致性备份，包括关键点、描述符、匹配和几何验证信息。
- 全部 `sparse/` 模型文件，以及 `report/` 和 `config.json`。
- 逐对匹配统计、相邻抽帧匹配、相机参数和按至少 15 个内点建立的连通分量。
- 每个采集文件的 SHA256 校验清单。

不包含原始视频和 ZIP。因为含完整图片与数据库，文件会比先前的精简回传报告大；实际大小由终端显示。默认限制未压缩内容为 512 MiB，超过时停止并说明原因；不要盲目扩大限制。

## 输出与原始数据

所有新增内容放在：

```text
/yinxin/projects/room/return_output/
├── diagnostics_reports/room_diagnostics_时间_随机编号/
│   ├── run/frames/
│   ├── run/database.db
│   ├── run/sparse/
│   ├── run/report/
│   ├── database_summary.json
│   └── manifest.json
└── room_diagnostics_时间_随机编号.tar.gz
```

源运行目录保留不动，重复采集创建新的目录。采集中发生错误时非零退出；已产生的诊断快照可能留在 `diagnostics_reports/` 供检查，不会用成功提示掩盖失败。复制和打包会额外占用磁盘，采集前检查空闲空间；时间戳归零以避免跨机器时钟差警告。

旧配置中的绝对路径仍指向服务器，不会自动适合本地运行；后续本地实验必须使用新的配置和输出目录。不要把多个独立模型叠加后当作同一个房间。

连通图只是诊断指标，不能代替三维几何验收。15 内点阈值用于定位弱连接，不是项目的质量验收阈值。相邻帧按照文件名排序，适用于本项目统一零填充的帧命名。

## 收到数据后检查

1. 对照抽帧与逐对匹配，定位重建在约 5 秒处停止的原因，并检查其他区域是否存在可用平移视差。
2. 核查相机初始焦距与优化结果。现有日志中初始为 1920 px，主要模型约 700 px；这是待验证线索，不是真实标定值，也不是已确认根因。
3. 在本地副本中做有依据的受控验证，给出点云/轨迹预览和覆盖说明，再决定继续调试或进入新算法对照。

数据库读取按 [COLMAP 官方格式说明](https://colmap.github.io/database.html)，并已用实际 PyCOLMAP 4.2.1 创建的数据库检查 schema 兼容性。该检查不代表本次服务器数据质量已通过。
