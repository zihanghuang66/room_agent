# 学校容器待处理项

## Codex 沙箱

报告显示普通进程能写项目目录，Codex 补丁在项目与 /tmp 都失败。模型总结提到 bwrap mount/source-path Permission denied，但缺少直接 shell 原始事件，不能确定是哪条 seccomp、AppArmor、namespace 或挂载策略导致。

v0.1.3 的直接检查因缺少 --permission-profile 参数而未执行；v0.1.4 已修复。先运行新版，只有原始输出确认了 sandbox_denied 后，请向学校管理员提供 sandbox_help.log、sandbox_project.log、sandbox_tmp.log 和 suite.json 的 sandbox 条目，请其确认容器模板是否支持 Codex 嵌套 Linux 沙箱，并提供平台批准的兼容配置。

验收：直接沙箱写入成功，随后真实 Codex shell 与补丁通过。root、chmod、普通 Python 写入成功，都不是沙箱可用的证据。

本包不使用 privileged、关闭沙箱、修改 seccomp/AppArmor 或增加宿主权限。具体被拒操作未确认前，不给出猜测性的权限修改命令。如果平台不支持，应使用平台批准的其他运行环境。打包 Docker 镜像不能单独解决宿主运行时限制。

## NVIDIA GPU 图形能力

实际 CUDA 渲染成功；EEVEE 只用 Mesa llvmpipe，libEGL_nvidia.so.0 / libGLX_nvidia.so.0 加载失败。当前没有可用 NVIDIA EGL 路径，不代表 CUDA 驱动整体损坏。/dev/dri 缺失只是附加观察，不单独判定 NVIDIA EGL 失败。

请求学校在启动容器时，为实际分配 GPU 启用 NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics，并由 NVIDIA 容器运行时注入匹配宿主驱动的图形库及 EGL vendor 配置。遵守动态 GPU 分配，不扩大到所有 GPU。

依据：[NVIDIA 官方 driver capabilities 文档](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/docker-specialized.html#driver-capabilities)。compute 支持 CUDA；graphics 支持 OpenGL/EGL/Vulkan；这些配置决定运行时挂载的驱动库。仅在已启动容器中 export 变量不会补上缺失挂载。

验收：NVIDIA EGL 图形库可加载，EEVEE 实际出图，renderer 不再是 llvmpipe/softpipe，并明确对应已分配 NVIDIA GPU。不能只看库存在或 nvidia-smi。

v0.1.4 会先查现有库与缺失依赖；仅对与当前宿主驱动版本匹配且加载成功的已有库生成本轮专用 EGL 配置，验证实际渲染。不在容器里安装/替换 NVIDIA 内核驱动，不用不存在或不匹配的库伪装成功。Cycles CPU/CUDA 已验证；完整 LiteReality 的 EEVEE 路径尚未替换与验收，不能据此声称整条流水线具备 GPU 渲染能力。
