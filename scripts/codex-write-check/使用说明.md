# Codex 文件写入诊断 v0.1.0

上一份 v0.1.1 报告中：视觉分类通过，本地 MCP 工具被调用，Codex 会话退出码为 0，但结果文件内容校验失败；stderr 包含 `Failed to write file .../result.txt`。不能将模型的 `DONE` 当作任务成功，也不能直接判定登录失效。

本包只诊断剩下的文件写入问题，不重复图片测试，不修改原有适配器，不改变 sandbox，不改权限或挂载，不使用跳过沙箱的选项。

## 完整命令

将 `room-codex-write-check-v0.1.0.tar.gz` 上传到 `/yinxin/projects/room/scripts/`：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-codex-write-check-v0.1.0.tar.gz
bash /yinxin/projects/room/scripts/codex-write-check/run_room.sh
```

依赖已经安装的 `litereality-agent-28ffe1f-room-codex-v0.1.1` 适配器、原 Python 环境和已登录的 Codex。不需要重新安装或登录。

## 测试内容

1. 用脚本本身验证测试目录可写，记录该目录的真实路径、权限、UID/GID 和对应挂载类型/选项。
2. 发起一次 `gpt-6-astra` 请求，使用已有 `workspace-write` 沙箱。
3. 要求调用本地 MCP 获取测试字符串，分别使用 shell + Python 和补丁/编辑工具写入两个独立文件。
4. 保存脱敏后的工具事件、工具错误和 CLI 诊断；即使 shell 失败，也要求继续独立测试补丁写入。
5. 脚本独立核对文件内容，拒绝把文件缺失、错误内容或符号链接判为通过。

这次会消耗一次 Codex 模型调用额度；实际是否执行两种工具及其返回结果以事件日志为准。结果仍只代表合成小测试，不代表完整 LiteReality 重建通过。

## 返回文件

结果和日志位于 `return_output/artifacts/room_codex_write_<时间>_<编号>/`。
终端会打印 `return_output/room_codex_write_<时间>_<编号>.tar.gz` 的完整路径，把该压缩包返回即可。

压缩包包括 `write_probe.json`、`tool_events.jsonl`、日志及哈希清单；不读取或打包 Codex 登录文件。时间戳固定为 0。脚本不会读取房间扫描或修改现有重建结果。

本包是诊断增强包，不预先宣称写入问题已修复。此前报告没有包含具体工具调用，尚不能区分沙箱、文件系统限制、编辑工具参数或其他原因。远程 `ps/mcp` 报错也不等同于本包的本地 stdio MCP 失败。
