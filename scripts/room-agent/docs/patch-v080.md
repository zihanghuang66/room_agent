# v0.8.0：以证据约束编辑

将这次三项修复抽象为：**先辨认当前结果 → 保留证据 → 检查前提 → 小范围修改 → 核验实际变化 → 独立验收 → 通过后替换**。

这是一套通用行为约定，不按房间名称、家具类别或特定报错匹配。床、柜子、椅子、墙面和材质编辑使用同一流程。

| 环节 | Skill 指导模型判断 | 代码核验与调度 |
|---|---|---|
| 理解 | 区分当前场景、历史评审与未接受候选 | 分开传入状态，不改写历史 |
| 规划 | 保留报告中的对象 ID、问题与视角；直接用户请求不编造证据 | 校验引用来自当前提供的报告，并随确认请求保存 |
| 检查 | 对象是否唯一、证据是否足够、现有工具能否按限制修改 | 三项前提及有效源码引用齐全才继续；否则返回具体问题 |
| 执行 | 小步保存，不扩大范围；部分编辑必须如实报告 | 实际文件哈希无变化则停止构建；部分修改或目标不一致只保留候选 |
| 验收 | 按确认范围独立检查，不接受作者自评 | 保留既有评分、覆盖率、几何与导出条件；通过才更新当前结果 |
| 中断 | 区分基础设施故障与场景质量问题 | 保留已有检查点；不把未执行的评审写成 0 分 |

## Skill 在哪里、怎样生效

唯一源文件：`src/room_agent/skills/spatial-edit/SKILL.md`。

规划、只读检查、编辑、独立评审四种角色由程序显式加载此文件到提示词。不是依赖 Codex 自行发现，也不需要用户安装到 ~/.codex/skills。角色原有工具限制不变。新确认请求保存 Skill 的 SHA256 和结构化 edit_contract，防止执行期间规则悄悄变化。

Skill 负责语义判断；代码不能凭文件哈希证明模型理解正确。哈希只说明文件是否变化。源码引用也只证明引用真实存在。对象身份、方法是否适合、外观是否正确仍由模型检查及最终验收共同判断。

## 缺少前提时怎样继续

同一 Conversation 显示“Your input is needed. Current result kept.”和具体问题。直接回答并确认新草案即可，不新增左侧 Task，不要求再次 Keep current result。新尝试从当前认可结果开始；未完成的候选仍留作诊断，不自动接着半成品编辑。

已满足要求且可从源码独立证明时，沿用无需修改分支。普通修改只有实际保存文件、报告完成且目标一致，才进入后续构建与验收。不能把“模型回复完成”当成“修改完成”。

例如，历史报告已明确对象 ID，后续不能丢掉 ID 再只说“桌子下的椅子”。但 ID 明确不代表网格局部可编辑；若仅有整体 GLB 且无法保持其他部件不变，应先说明能力缺口，而不是渲染半小时后失败。

## 兼容边界

- 已存在任务、成果、评审与检查点原样保留；旧请求继续原策略，不事后改判。
- 新策略用于升级后新确认的会话编辑。旧草案需重新发送以生成完整证据绑定。
- 最新旧操作若还显示 Edit not accepted，先 Keep current result，再在原 Conversation 提问。不要 Resume 旧操作来测试新策略。
- 此改动不修改 ingest/reconstruct，不自动重跑房间，不降低验收标准。

## 验证边界

本地测试核验结构化证据、阶段路由、源码变化、恢复复用、同会话继续与 UI 按钮状态。模型会话使用可控替身；学校服务器上的真实 Codex 判断、GPU 构建及场景质量仍需验收。不会以本地单元测试声称模型已能修好任意神经网格。
