# v0.10.1 — 计划目标约束与失败诊断

## 现场结论

返回包中最新对话显示 scene_review=true、resume_operation=null、active_operation=null；保留版本仍编辑验收通过。本次失败发生于计划校验，未提交复评。

旧校验错误把字段不匹配、会话目标错误与未清空澄清问题合并，且未保存被拒绝的原始计划，因此无法断言这次是哪一个条件。场景会话 ID 与实际保留版本 ID 不同，旧模型 schema 未限定目标字符串，是可复现的协议薄弱点。

## 修正

- 生产 Planner 直接接收宿主上下文，按轮深拷贝 schema：target_run_id 的 enum 只有当前会话 ID；operation 仅包含当前可提供的操作；operation_run_id 仅允许空字符串和实际允许恢复的运行 ID。
- 提示词明确区分会话 ID、保留场景 ID、恢复操作 ID。不解析用户文本提取目标，不自动把陌生目标替换成当前目标。
- 继续严格校验。将原合并错误拆成字段差异、目标差异和未解决问题，不放宽场景或确认规则。
- 失败轮保存有界 planner_output 到每轮诊断 JSON；成功轮不重复保留完整模型输出。原始模型输出过大时标记截断。
- 不改变执行器、队列、质量标准、已有任务、场景或检查点。没有自动重试模型或自动运行复评。

## 验证

新增测试穿过生产 Planner → 实际 --output-schema 写入 → 解析 → 校验通道，使用不同的会话与源版本 ID；验证 schema 按会话隔离、恢复 ID 限定、错误目标仍拒绝、失败原始输出保存及不同错误分类。模型响应在本地模拟；学校实际模型还需再次发送原指令验证。
