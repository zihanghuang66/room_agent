## Resume semantics

Previously every uncommitted stage restored the last successful stage snapshot, moving the failed workspace aside. Now first execution still starts from that snapshot, but a retry with a matching previous attempt retains the current workspace. Before starting a worker, it copies and inventories the saved scene to work/failed/<stage>/before-resume-*/scenes and writes a checkpoint manifest. Input capture, request, pinned backend and published stage integrity are still checked. A missing working scene or missing Author Room.py stops with an explicit error; no silent rollback.

For Author that reached acceptance (author_acceptance.json exists), the retry calls the pinned acceptance.finish on the current saved Room.py: rebuild, geometry/support checks, paired rendering and independent visual review, then bounded repair if needed. It does not repeat initial Author, object refinement or materials passes. Limits remain 2 repair rounds, 40 tool calls per repair session and 600 seconds; no unbounded automatic retry or lowered quality gate. Failure/timeout details are retained. Resume means new bounded work on saved source, not restoration of the prior model conversation.

If Author stopped before acceptance, it re-enters the original Author stage using the saved room. Other attempted non-Prepare stages also retain their workspace while re-entering their stage function; internal operation reuse depends on that stage's existing implementation. Prepare still re-extracts uncommitted input to preserve capture integrity.

The current saved code can be newer than the last render. Therefore a resume must rebuild and reassess it; an older successful image is not treated as proof of acceptance.

## Compatibility

engine_compatibility.json explicitly maps the verified v0.4.0–v0.4.3 execution fingerprints to this exact release's fingerprints. Modified current code and unknown old versions are rejected. Immutable input.json and LangGraph checkpoints are not edited. Both pinned reconstruction and saved-review backends remain byte-identical. Saved-scene review execution remains unchanged apart from the explicit release compatibility check.

## Results and Diagnostics

Results is the default tab. Full scans show successfully published stage outputs only; earlier failed acceptance rounds in a published snapshot are not used as comparisons. This is stage completion, not a claim that an initial Seed scene passed final visual acceptance. Unpassed saved-scene reviews are routed to Diagnostics.

Diagnostics separately exposes saved backend comparisons, matching render exports, reports and other attempt files. Drafts never replace the Results tab. No failed/unapproved labels are added to the clean main results area. Initial scene means Seed assembly.

## Two archives

The existing full archive remains unchanged (it already excludes certain recovery snapshots; it is not a complete disk backup). A diagnostics archive adds bounded report/text collection and up to six paired images, excludes models/Blender files, capture trees, credentials and recovery snapshot trees, and records truncation/omissions in diagnostics_manifest.json. Default file content budget is 24 MiB plus archive/index overhead; logs are tailed above 512 KiB. It is not a restorable scene.

Web-launched workers create diagnostics after the existing full packaging/process exit. Download diagnostics generates it on demand for existing stopped tasks. Full bundle retains the original behavior. collect_diagnostics.sh RUN_ID creates only the small archive; collect_return.sh RUN_ID produces both. Both live under project/return_output and have zero archive timestamps.

## Validation boundary

Local tests cover retained Author edits, retry after another interruption, missing-source refusal, v0.4.3 request/receipt compatibility, exact fingerprint checks, direct acceptance dispatch, published-vs-draft display separation, compact archive limits and exclusions, and automatic small packaging after worker exit. Blender/GPU/Codex model quality is not validated locally; the school run must still satisfy the independent acceptance gate.
