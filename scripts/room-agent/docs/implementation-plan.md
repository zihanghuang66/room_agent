# Room Agent 分层迁移计划

**Goal:** 支持多个房间的持续交互、阶段预览、失败定位和基于已有结果的恢复。

**Architecture:** 客户端调用统一应用服务；LangGraph 管理任务控制状态；执行器负责 Codex、Blender、TRELLIS。文件保存不可变输入和产物版本，检查点保存执行位置，报告是可重建的投影。先保留原有完整入口，逐步迁移，不改变算法和质量标准。

**Tech Stack:** Python 3.11+、LangGraph、SQLite（第一阶段本机验证）、pytest。后续服务化的数据库与任务队列需独立验收。

用户已批准分层方向和开始实施；按阶段在当前会话执行，每阶段自检。GitHub 推送必须另行获得用户确认。

## 状态契约

`room_id` 标识房间；`run_id` 标识一次操作并用作 LangGraph thread_id；`revision_id` 标识快照。后续对话 ID 独立，不把整个房间绑定到一个无限增长的对话。

LangGraph 检查点是执行状态权威；`input.json` 是不可变请求，`manifest.json` 是产物校验依据；`result.json` 由检查点派生，不参与恢复决策。旧 pipeline.json 在迁移阶段仍是旧执行器内部状态，不让两套状态同时决定同一节点的执行。

节点恢复会重放节点，并非从 Python 语句中间继续。所有外部副作用必须使用稳定操作 ID、原子发布与复用校验；长 GPU 任务需阶段 2/3 的独立任务记录和恢复策略。
