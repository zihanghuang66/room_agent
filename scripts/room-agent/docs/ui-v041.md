# v0.4.1 UI correction

New scans have one Start Reconstruction button. It creates prepare_only=false tasks; the existing prepare node validates input before the remaining stages. Old prepare-only tasks remain readable. This release does not alter graph execution, queue dispatch or backend models.

Workspace reads lifecycle timestamps from the existing event endpoint. Most recent run_started sorts first; run_created is the fallback for unstarted tasks. Stage progress and selecting a task do not affect ordering. Incremental event reads use sequence cursors, bounded concurrency of four and a 15-second cache for unchanged inactive tasks. Activity timestamps are shown on cards. If events cannot be read, preserve the cached time, or put unknown time entries last. Queue execution remains FIFO.

The existing Python execution files are byte-identical to the v0.4.0 delivery, preserving engine hashes and checkpoint compatibility. Source HTML, tests, release metadata and documentation change. No input/checkpoint rewriting is performed. Old versions prior to v0.4.0 are not covered by this compatibility statement.
