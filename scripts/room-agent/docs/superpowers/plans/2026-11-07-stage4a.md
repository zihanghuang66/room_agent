# Stage 4A implementation plan

Goal: create isolated, instruction-driven revisions from existing completed scenes without ingest or reconstruction.
Architecture: an additive `scene-edit/1` LangGraph workflow; existing graphs and immutable requests remain unchanged. Each child binds its parent run, source/capture hashes and instruction. Saved editing is consumed at most once; downstream checkpoints can retry. Codex edits source, Blender builds and renders, independent review retains the existing score >=8 / all objects / zero issues standard.
Tech stack: Python, LangGraph SQLite checkpoints, existing Codex and Blender adapters, existing English HTML UI.

Approved scope: explicit version selection and change instruction, isolated child revision, matched before/after and captured/rendered views, preserved history, diagnostic export. Free-form conversational routing is deferred to 4B. No destructive rollback, automatic quality repair or reconstruction.

- [x] Phase 1: `revisions.py`, Service create/list revisions, immutable snapshots. Test completed full scan and child selection, room identity, parent integrity and source mutation rejection.
- [x] Phase 2: `edit_graph.py`, `edit_executor.py`, `edit_driver.py`. Test single edit attempt, interrupted-edit retention, downstream retry without replay, strict geometry/quality outcome, per-group review reuse, matched camera IDs. Use existing build/export verification, no backend reconstruction calls.
- [x] Phase 3: HTTP/CLI create-edit; English revision selector and instruction form; before/after preview on same cameras; unapproved outputs only in Diagnostics. Test real HTTP queue and JS UI events, no parent execution.
- [x] Phase 4: full regression, release compatibility, extracted source-only package verification, foreground launcher and complete school acceptance instructions.

Validation boundary: local tests can exercise real graph/checkpoints/HTTP/queue and mock external GPU/model services. Actual new-scene editing, Blender rendering and model quality must be accepted in the school container; do not claim those ran locally.

Risks: copying scene assets requires disk; matched camera rendering adds cost. A requested design change is judged against the instruction while unchanged scene content remains grounded in capture. Lack of coverage remains a failed quality check. `Completed with issues` is an executable version, not quality approval. Parent selection does not modify any scene.
