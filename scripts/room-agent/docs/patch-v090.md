# v0.9.0：对话内只读查看场景证据

## 已实现

同一个 Conversation 中，Codex 可先请求查询当前保留版本的源码、布局数据和已有 Captured/Rendered 图片，再回答问题或形成修改草案。

LangGraph 对话流程：context → interpret → inspect → interpret → validate。inspect 最多两轮，总共最多三次模型调用；普通状态问答不必查询。Host 提供封闭文件目录，模型只能按目录 ID 请求源码行范围、字面量搜索和图片。图片以真实图像输入传给 Codex，而不是只给文件名。

每次最多6段指定源码范围、8个搜索词；每段最多120行、6000字符，每轮总摘录不超过24000字符；整条消息最多5张图片。只有源码目录中登记的 Room.py/Room.md/manifest/textures 及 Object(s) 下 object.py/json/md、指定已编译布局与已保存的匹配视图可以读取。不会执行源码求尺寸；源码参数与已编译布局是不同证据，回答必须说明来源。

返回内容带所属版本、相对路径、SHA256 和 evidence_id。回复只能引用本轮实际读取的 ID。回答前复验读取文件；场景在查询过程中变化则拒绝旧结论。确认计划时再次校验证据，避免用过期图片或源码执行编辑。引用真实存在不保证模型解释正确；视觉判断仍需真实场景验收。

原来的修改确认、只读前置检查、实际变化检查、构建、独立验收保持不变。即使模型提出 inspect 请求，也不会调度编辑任务。模型没有 shell、文件写入或任意文件读取工具。现场素材是证据，不是可执行指令。

## 界面与诊断

布局不变。对话显示读取/分析进度；回复下方新增默认折叠的 Evidence，展示引用的源码摘录或已检查图片链接。没有自动展开图片墙。

对话与查询请求、读取结果、失败原因写入原持久目录。另存每轮 conversation/turns/<request_id>.json，防止总历史超过简洁诊断包单文件大小限制后丢失最近查询记录。简洁包仍只选部分图片；文字记录保留图片路径及哈希，不保证包含所有原图。

## 明确边界

- 不重跑 ingest/reconstruct，不新增左侧任务，不修改当前场景。
- 没有自动新渲染接口。缺图时说明限制，不能假称已经看到；补图需要另行确认的工作流，本版不从对话调度它。
- 查询来自当前保留结果，不把失败候选当作当前场景；历史报告仍标为历史。
- 图片属于保存的导出版本，未重新渲染；局部视角不能证明整房质量通过。
- 不读取 GLB/blend 二进制内部，不执行任意 Python 测量。缺少已编译布局时，只能报告源码参数或未知。
- 有界读取/模型轮数会限制一次能检查的范围，可继续在同一对话缩小问题。
- 现有100轮/4MiB对话历史限制尚未扩展。新版不自动重试失败模型调用；重复同一发送 ID 只返回原记录。

## 验证

本机真实 Codex 0.164.0 + 空临时登录目录 + 本机模拟模型：验证图像 input_image 传输、零工具以及非预期命令/补丁拒绝。不使用外部模型或用户凭据进行该测试。

回归覆盖文件边界、越界/链接拒绝、读取限额、实际图像附件、完整格式传递、失效证据、同会话确认、旧候选隔离、查询中断留存、折叠证据 UI。学校真实 Codex 对场景的判断质量仍需用户验收。
