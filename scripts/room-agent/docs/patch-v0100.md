# v0.10.0 — 对话确认复评与恢复

## 已实现的范围

- `scene_review`：在同一 Workspace/Conversation 中，基于当前保留版本创建内部独立复评。流程为 snapshot → preflight → build → geometry → evidence → render → review → decision。固定 max_batches=0，不修改源场景、不自动修复、不运行 ingest/reconstruct。几何检查未通过时按原规则结束，不能伪造视觉评分。
- `resume_operation`：绑定当前允许恢复的原运行 ID，确认后由原 LangGraph 检查点继续；既支持会话内编辑/复评，也支持中断的原始任务。没有可恢复任务时只能解释状态，不创建新的重建。
- 发消息只产生草案。Confirm & run 才提交。等待人工 decision、运行中、正在保存诊断、已完成等状态不能当作中断自动恢复。
- 恢复确认先持久化，再用 plan_id 作为队列提交标识。即使排队成功后回复丢失、任务很快再次失败或服务重启，同一次确认也不会重新提交。新的恢复尝试需要新的草案及确认。

## 结果与来源

复评无论质量通过还是未通过，正常完成后都解除操作占用。只有技术执行异常才进入失败/恢复状态。复评不推进当前场景指针，不替换下载文件，不将质量未通过称为编辑失败。

报告绑定源版本、源码/种子和采集文件内容。源文件变化后报告标为过期，不再提供当前评分。文件哈希仅在 inode、size、mtime、ctime 均未改变时复用；目录清单每次检查。执行仍独立使用原完整校验。

通过的复评图片和报告投影到 Summary；未通过的图片仍留在诊断，不混入通过的 Snapshot。对话查询可以读取有效复评图片，展示 Evidence 缩略图。后续编辑保留该复评为历史基线，继续区分局部编辑验收与整房质量。

## 兼容与验证边界

旧 input、检查点和队列数据不迁移、不改写；TaskQueue 仅新增可选提交标识，旧调用保持原语义。执行图、模型提示词中的质量标准和已完成节点复用方式不变。兼容列表只允许明确的发行指纹。

本地测试使用真实 LangGraph/SQLite/HTTP/持久队列，替换昂贵模型和渲染适配器；覆盖复评版本选择、仅失败节点续跑、旧完整扫描恢复、重复确认、丢失回复、过期输入、报告继承、UI 和原编辑回归。本地通过不代表学校 GPU 与真实模型已经验收。

本版不支持从对话启动新扫描、指定新相机补图、自动连续修复或并行 GPU 调度。
