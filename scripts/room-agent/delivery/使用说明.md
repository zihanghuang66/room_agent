# Room Agent 第二阶段服务器验收包 v0.2.0

这是待学校服务器验收的版本。已接入真实已有场景构建、几何校验、对照渲染和 Codex 独立评审；本地控制流与网页测试不能代替学校环境全链路验收。

## 一次启动

上传 `room-agent-stage2-v0.2.0.tar.gz` 至 `/yinxin/projects/room/scripts`。

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-agent-stage2-v0.2.0.tar.gz
cd room-agent-stage2-v0.2.0
bash start_server.sh
```

脚本在前台运行。不会自动创建 tmux，也不使用 background。会验证包内容、创建独立编排环境、按锁定版本安装依赖、检查持久目录读写/跨进程锁/SQLite 恢复、运行自检，然后启动网页服务。

编排环境：`/yinxin/projects/room/scripts/.room-agent-stage2-v0.2.0-env`。不修改 `/opt/room/envs/app`、GPU 环境、Blender、Codex 安装及登录。首次安装需要能访问配置的 Python 包索引；不会下载模型或 Codex 二进制。

如果只想先检查安装：`bash start_server.sh --check-only`。这不等于真实场景验收。

## Mac 打开网页

在 Mac 运行压缩包内的 `forward_mac.sh`。脚本会询问学校页面**当前容器的 SSH 地址、端口和用户名**，不要沿用旧容器端口。

```bash
bash forward_mac.sh
```

SSH 连接成功后打开 `http://127.0.0.1:8765`，转发终端保持运行。服务仅监听容器回环地址，不需要向校园网公开新端口。若 SSH 转发被学校策略禁止，保留具体 SSH 错误反馈，不能用公开绑定绕过策略。

页面关闭或刷新不会停止服务器任务；停止服务器上的 start_server.sh 会停止本服务启动的工作进程并保留状态。重新启动相同脚本，选择原任务“复评 / 继续”，不要重新创建任务来冒充恢复。

## 网页验收步骤

1. 从“已有运行目录”下拉框选择**要继续的 room_004 那次完整服务器运行**。列表显示完整目录名。不要选仅解压返回包的副本；原始 capture、初始 seed 和已保存源码都必须仍在。
2. 保留默认“最多 1 批修复、每批 900 秒”，点击“创建并开始”。这不会自动修改场景；独立评审完成后才提供“修复一批”按钮。设置 0 则只复评，完成后本任务不能再追加修复。
3. 观察节点：输入快照 → 环境预检 → 构建 → 几何及导出重开 → 选择视角 → 对照渲染 → 独立评审。页面每 2 秒更新日志和状态；图像在对应渲染完成后出现，没有伪造实时百分比。
4. 环境预检会实际调用 Codex 返回标识，确认服务可响应；还检查 Blender、FCL、rtree、ffmpeg。不会只凭 `codex --version` 报登录通过。
5. 几何检查未通过会进入等待选择或结束，不绕过碰撞检查去宣称视觉通过。检查库不可用属于技术失败。视觉评审 score>=8 且所有对象已核实、无问题才算质量通过。
6. 若需要修复，查看问题后点击“修复一批”。仅编辑复制的源码，保留原始结果；重新构建、检查、渲染和独立评审。修复超时会保留已保存修改并复评，仍单独显示 timeout/interrupted；不会把超时等同于质量失败。
7. 在一次暂停或结束后下载“返回包”。把 tar 发回，以便核对实际节点、耗时、产物、原始输入指纹和失败原因。

建议先验收实际复评，再验收一个修复批次；视觉质量不通过不等于本阶段程序运行失败。

## 输出与续跑

- 持久状态、节点收据、日志及产物：`/yinxin/projects/room/return_output/agent_state_stage2_v020/`。
- 场景返回包：`/yinxin/projects/room/return_output/room_agent_stage2_<RUN_ID>.tar.gz`。每次结束、等待操作或失败自动生成；网页也可以重新下载。
- 安装/启动诊断：`return_output/environment_reports/room_agent_stage2_setup_*`；启动脚本退出时输出诊断 tar 路径。
- 如网页不可用，在包目录运行 `bash collect_return.sh RUN_ID`。RUN_ID 在网页任务详情中显示。

返回包只供分析和导出查看，不是可迁移的完整工作目录，不包含原始 RGBD、模型权重、账号或 Codex 凭据。模型/材质可能让返回包较大；上传代码包本身不包含这些大文件。所有 tar 的成员时间固定为 0。

成功节点会记录完整输入和产物指纹。技术失败后仅恢复未完成节点。节点内部中断仍可能需要重跑该节点；不宣称 GPU 从指令中间恢复。未完成的修复若已有保存源码，会先复评它，不悄悄丢弃后重新编辑。

## 明确边界

- 没有网页聊天输入，也没有自然语言指令理解；Codex 只用于流程中的预检、选视角、独立评审和明确触发的修复。
- 本次不重新 ingest/reconstruct、TRELLIS 或参考图生成。保留原有算法、视角选择及质量门槛；只把现有执行能力拆成可观察节点。
- 一个服务同时执行一个任务；编排器持有全局场景执行锁防止自身任务争抢资源，但不会停止其他训练任务。
- 启动存储探测验证同容器进程间锁与重开，不是跨主机或断电保证。多主机生产部署不在本阶段范围内。
- 三天容器重建后，目录仍保留的前提下重新运行 start_server.sh；Codex 是否需要重新登录由当前环境决定。不要修改已完成版本目录或调低检查阈值来绕过验收。

## 实际验收要返回什么

优先发场景 `room_agent_stage2_<RUN_ID>.tar.gz`；若网页还没启动成功，发 `room_agent_stage2_setup_*.tar.gz`。同时说明选择的是哪个原始运行目录，以及浏览器是否显示节点与预览。
