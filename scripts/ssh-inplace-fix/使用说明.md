# 在学校当前 r4 容器中修复 SSH 并保存镜像

不需要在容器里安装 Docker，也不需要构建另一份 r5。脚本应在学校管理页面的网页 Shell 中以 root 执行。

## 1. 上传和修复

将 room-ssh-inplace-fix-v0.1.0.tar.gz 上传到 /yinxin/projects/room/scripts，然后：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-ssh-inplace-fix-v0.1.0.tar.gz
bash room-ssh-inplace-fix-v0.1.0/repair.sh
```

脚本补齐 /usr/sbin/sshd 的初始化入口，并调整服务脚本的进程匹配。保留当前主机密钥、系统 SSH 配置和登录账户配置；验证配置、重启服务并检查本机 SSH banner。底层机制沿用已测试的直接 sshd 修复；本包做了静态语法校验，未额外启动镜像测试。

必须看到 REPAIR_OK，失败时先回传终端输出或 RETURN_TAR 文件，不要继续保存。结果包位于 return_output。

## 2. 在保存前清除本容器主机密钥

先确认 Mac 能连接当前容器，然后回到网页 Shell：

```bash
bash /yinxin/projects/room/scripts/room-ssh-inplace-fix-v0.1.0/prepare_save.sh
```

此步会停止 SSH，并删除本容器生成的 SSH 主机密钥，避免克隆出的容器共享同一身份。网页 Shell 必须保持可用。脚本不会清除 authorized_keys 或账户密码，也不会备份主机私钥到待保存镜像中。

看到 SAVE_IMAGE_NOW 后，点击平台顶部“保存镜像”，建议使用新名称：room-litereality-agent-ssh-fixed-20261102。等平台明确显示保存完成，期间不要重启 SSH。

## 3. 保存完成后

如果继续使用当前容器，在网页 Shell 执行：

```bash
service ssh start
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

此时会生成新的主机密钥。Mac 如提示主机密钥改变，应先与网页 Shell 指纹核对一致，再删除对应地址/端口的旧 known_hosts 记录。不要关闭主机密钥检查。

使用保存的新镜像创建新容器后，按平台分配的新地址和端口验证 SSH。修复能覆盖启动脚本、service 及直接 sshd 的路径，但如果平台完全没有启动任何 SSH 命令，仍需平台使用 start-ssh.sh 或 sshd；镜像无法自行改变平台启动策略。
