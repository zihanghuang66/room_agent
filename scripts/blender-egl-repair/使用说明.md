# Blender EGL 修复与复测 v0.1.0

针对上一份报告中的 `Couldn't open libEGL.so.1`。已安装的 Blender 5.1.2、CPU/CUDA 渲染和 GLB 导出均成功，本包补齐容器中的图形库并重新验证三个渲染后端。不会重新下载 Blender，不读取扫描，不运行房间重建，不调用收费 API。

## 完整运行命令

将 `room-blender-egl-repair-v0.1.0.tar.gz` 上传到 `/yinxin/projects/room/scripts/`，然后执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-blender-egl-repair-v0.1.0.tar.gz
bash /yinxin/projects/room/scripts/blender-egl-repair/run_room.sh
```

无需另外上传旧脚本或 Blender 安装包。本包包含启动、检查、渲染测试所需脚本，复用现有程序：

`/yinxin/projects/room/return_output/tools/blender-5.1.2-linux-x64/blender`

## 自动执行内容

1. 记录 EGL/OpenGL/NVIDIA 用户态库能否加载、EGL vendor 配置、相关容器环境变量。
2. 根据缺失项安装 `libegl1`、`libgl1`、`libopengl0`，使用系统现有 APT 源及 `--no-install-recommends --no-upgrade --no-remove`。只有缺库时才执行安装。
3. 在实际安装前检查 APT 模拟计划；若计划移除软件或涉及 NVIDIA/CUDA/内核驱动包，停止自动安装。
4. 重新检测图形库，分别执行 Cycles CPU、CUDA、EEVEE 的小立方体渲染，并导出测试 GLB/Blend。
5. 检查进程退出状态、结果 JSON 和 PNG；记录 EEVEE renderer/vendor，明确标记识别到的软件渲染。渲染器查询失败会保留错误，不能因此认定 GPU EEVEE 已验证。
6. 自动打包结果，成功或失败都尽可能留下返回包。

已有报告显示 Ubuntu 22.04。本包要求 Linux x86_64、Python 3.10+、已有 Blender；安装库需要 root 或免密 sudo，以及可用的 APT 软件源。不会提示输入密码；权限或 APT 失败将进入报告，仍会尝试复测。单项渲染超时为 10 分钟。生成图像是测试立方体，不是 room_002。

## 返回文件

终端最后打印：

```text
RESULT: ...
RETURN ARCHIVE: /yinxin/projects/room/return_output/room_blender_egl_<时间>_<编号>.tar.gz
```

把该压缩包返回即可。明细全部位于 `return_output/artifacts/room_blender_egl_<时间>_<编号>/`，项目根目录不新增运行产物。tar/gzip 时间固定为 0，避免未来时间警告。报告不读取或打包登录文件；APT 日志中的 URL 用户名/密码和常见查询凭据会脱敏。

- `blender_checks_passed`：三个合成渲染检查通过；查看 EEVEE 的 renderer 才能进一步判断实际图形后端。
- `eevee_software_only`：检测到软件渲染，不能当成 GPU EEVEE 已通过。
- `blender_checks_incomplete` / `failed`：查看 `result.json`、APT 日志及 `render_eevee.log`；返回压缩包进一步判断。

只诊断和复测、不安装软件：

```bash
bash /yinxin/projects/room/scripts/blender-egl-repair/run_room.sh --check-only
```

## 如果 EGL 装好后仍然失败

CUDA 可用不代表 NVIDIA 图形驱动库已挂载。若报告显示 NVIDIA EGL 库或 vendor 配置仍不可用，需要结合 EEVEE 错误确认学校启动容器时的图形能力。

通常应在创建容器时包含 `NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics`，并保留学校分配的 GPU；仅在已运行容器里 export 该变量不会补上驱动挂载。本包不改变 GPU 分配、不安装宿主 NVIDIA 驱动、不伪造 NVIDIA vendor 文件，也不会用软件渲染掩盖 GPU 图形问题。

依据：[NVIDIA Container Toolkit — Driver Capabilities](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/docker-specialized.html#driver-capabilities)。是否缺挂载尚待本次报告确认。

安装的系统库位于当前容器系统层；三天后重建容器可能丢失。可重跑本包，或在后续自定义镜像中固定这几个系统依赖。项目内 Blender 本体仍在持久化目录。

发布前验证使用模拟 APT/Blender 的编排测试及本地静态检查，不等同于学校服务器的真实安装和渲染验证。
