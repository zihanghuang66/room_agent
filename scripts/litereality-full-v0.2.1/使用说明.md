## 运行范围

1. 对原始 tar 计算 SHA256，安全解压，检查全部帧的 RGB/深度/相机 JSON 文件是否配对。
2. 校验固定应用，复用环境变量 ROOM_CODEX 或 PATH 中现有的 Codex；记录版本，现有登录继续使用。不附带、下载或安装 Codex。
3. 应用/MCP、GPU 可用显存和算子、Blender CPU/EEVEE、真实 Codex 命令写入与 MCP 调用、模型加载检查。
4. ingest：RoomPlan/RGBD 解析、视角选择、家具分类与 Codex 内置 imagegen 参考图。
5. reconstruct：TRELLIS/程序化家具构建、椅子检查、GLB 有效性检查。
6. seed：场景布局装配，原始捕获路径和全部相机数量复核。
7. author：场景编排、物体细化、材质、质量改进、独立几何与视觉验收。
8. publish：仅验收通过才发布，再打包 Blender 贴图并重开 BLEND/GLB 检查。

“全量”指上述完整流程，不表示对每一帧都单独调用图像模型。全部输入帧检查配对，参考图按上游视角评分选择；现有正式验收使用 6 个视角。修模仍限 2 轮，每轮 40 次工具调用/600 秒；未降低 >=8 分等验收门槛，因此新场景仍可能因质量或证据不足而不通过。新扫描家具数量未经人工确认，记录在 scene_inventory.json，绝不当作真实数量保证。

author/publish/重开检查失败时，在有可用 authored Room.py 的情况下，额外尝试重建并导出 `candidate_preview/Room.glb`、`candidate_preview/Room.portable.blend`。该目录的 candidate_status.json 明确标注未通过验收；失败退出码保持非零。候选导出也失败时会记录错误，不声称已经提供可用模型。

## 依赖与资源

使用已准备好的 LiteReality Linux x86_64 容器镜像、已登录并启用 image_generation 的 Codex、已申请的 NVIDIA GPU。包内仅含修复后的应用与运行脚本，不包含 Codex 运行时。复用容器现有 Codex、GPU/Python/Blender/TRELLIS 环境，不需要旧的 full/resume 脚本目录。先检查 Codex 版本，再以真实命令写入/MCP 调用验证环境是否可用；检查失败时输出报告，不自动重装。

遵守 CUDA_VISIBLE_DEVICES，使用可见 cuda:0，不指定学校物理显卡编号。启动要求其可用显存至少 18 GiB，初始 TRELLIS 分辨率 512。运行消耗 Codex/图像生成额度和 GPU 时间，耗时取决于家具数量；不会上传凭据或改登录。默认最多 64 次参考图生成会话，触顶停止并报告，不无限重试。

共享已缓存的模型权重，新的重建输出独立。tar 解压上限 32 GiB，超出需调整；运行途中仍可能耗尽磁盘，平台回收/断电/SIGKILL 也无法保证最后的压缩打包完成。
