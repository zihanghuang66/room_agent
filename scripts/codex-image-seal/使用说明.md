# 将完整 Codex 固化进现有 Room 镜像

适用：Linux x86_64 Room 容器，已有 room-litereality-full-v0.1.0 与解压后的 room-litereality-resume-v0.1.1。先等待正在运行的 room_002 任务结束，安装器会检查运行锁。

无需在学校容器中安装 Docker。本包使用之前修复包内的官方 Codex 0.164.0 完整归档，不再下载，也不重复上传 162 MB。

## 1. 安装并验证

上传本包到 `/yinxin/projects/room/scripts`：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-codex-image-seal-v0.1.0.tar.gz
bash room-codex-image-seal-v0.1.0/install.sh
```

安装位置是容器镜像内部 `/opt/room/tools/codex-complete-0.164.0`。安装器先检查该目录没有单独挂载、校验官方归档 SHA256、校验完整安装内容，再切换三处 Codex 入口：`/opt/room/bin/codex`、`/usr/local/bin/codex` 和 `/opt/room/tools/codex-packaged/bin/codex`。旧入口与 environment.sh 保存在 `/opt/room/build-info/codex-seal-backups/`。

本步骤不停止 SSH、不重建房间、不移动权重、不修改或复制 Codex 登录文件。会使用现有登录进行一次真实命令读写和 MCP 调用，通常需要几分钟。成功必须显示：

```text
INSTALL_OK ready_for_save_preparation
```

失败时不要继续保存，回传终端错误或打印的 RETURN_TAR。返回包命名沿用原打包器，为 `return_output/room_002_full_codex_seal_<UTC>_<随机码>.tar.gz`。

## 2. 保存前准备：只在平台网页 Shell 中执行

```bash
bash /yinxin/projects/room/scripts/room-codex-image-seal-v0.1.0/prepare_save.sh
```

它先复核固化文件及真实执行测试已通过，再调用已用于本项目的 SSH 保存前处理：停止 SSH、删除当前容器生成的 SSH 主机密钥，保留自动生成密钥的启动修复。此步会断开 SSH；保持平台网页 Shell 打开。不会修改账户密码或 authorized_keys。

看到 `SAVE_IMAGE_NOW` 后，在学校平台点击“保存镜像”，建议新名 `room-litereality-agent-codex-complete-20261103`。等待平台明确完成后，才能恢复当前容器的 SSH：

```bash
service ssh start
```

沿用此前已验证的 SSH bootstrap 是前提；如果脚本报缺少标记或 PID 1 监管 SSH，则先回传错误，不要自行强行停止容器。

## 3. 用新镜像新建容器验证

```bash
/usr/local/bin/room-codex-runtime-check
codex --version
```

应返回 status=passed、完整 CLI/host 路径位于 `/opt/room`。这项检查不需要登录，但真实 Codex 请求仍使用该容器可用的账号登录。

固化的是 Codex 运行组件及全局入口。扫描、模型权重、项目代码和重建结果继续放在持久化 `/yinxin/projects/room`，不复制进镜像。此前续跑包仍自带同版本运行时；即使项目挂载不可用，新镜像的全局 Codex 组件也应完整。学校实际保存行为仍须以上面的新容器检查确认。
