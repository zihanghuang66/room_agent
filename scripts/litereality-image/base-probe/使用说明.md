# 学校内网基础镜像探测 v0.1.0

用户提供的平台镜像名称：`10.27.130.24_5000_pytorch_pytorch_21.10-py3`。
按常见平台命名规则推测其实际地址为 `10.27.130.24:5000/pytorch/pytorch:21.10-py3`；**该转换尚未由学校确认**，本探测同时验证它是否可拉取。若详情页给出的地址不同，以详情页为准，替换 Dockerfile 第一行 ARG 的值。

将 `room-school-base-probe-v0.1.0.Dockerfile` 上传到学校的镜像构建入口，必要时重命名为 `Dockerfile`，架构选择 linux/amd64。镜像名可填 `room-base-probe:0.1.0`。

无需启动容器、分配 GPU、解压或安装依赖。拉取基础镜像后，构建日志会输出 `ROOM_BASE_PROBE_BEGIN` 到 `ROOM_BASE_PROBE_END` 之间的 JSON；请把这段日志发回来。若停在 FROM，返回该错误即可。结果也保存到探测镜像的 `/opt/room-base-probe/report.json`。

一次检查：系统与 glibc、Python、现有 torch 包版本、nvcc/GCC、CUDA 目录、GitHub/PyPI/PyTorch/Blender/Node/NVIDIA/Hugging Face 的 HTTPS 证书与响应。外网请求只发 HEAD，不下载完整安装包，不关闭证书验证，不读取密钥或输出环境变量。

如果构建报内网仓库 HTTP/HTTPS 协议不匹配、认证失败或镜像不存在，需要平台提供正确拉取地址/授权/构建器仓库配置；不能通过容器内部 RUN 命令修复。

这是诊断镜像，不是 LiteReality 运行镜像，不应把“探测构建成功”当成安装完成。原完整配方 v0.1.1 保留，不能只把其 FROM 替换成旧基础镜像后直接使用。

条件依据：如果该镜像确为 NVIDIA PyTorch 21.10 的镜像副本，官方发布配置为 Ubuntu 20.04、Python 3.8、CUDA 11.4.2、PyTorch 1.10 开发版；学校是否修改过还需本次实际输出确认。
