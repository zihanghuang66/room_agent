# 保存场景的分批修复与独立复评 v0.1.0

上传本压缩包到 `/yinxin/projects/room/scripts` 后执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-litereality-batch-review-v0.1.0.tar.gz
bash room-litereality-batch-review-v0.1.0/run_room_004.sh
```

前台运行；不启动 tmux，不加 background。使用当前容器已有的 Python、Blender、Codex 登录和 GPU 分配，不下载模型或 CLI。

## 本次做什么

1. 明确读取 room_004 的原结果目录 `room_004_test_04_full_v0.3.0_3f98a38f7e61`，核对 v0.3.1 应用来源。原目录名是旧版本名，输入记录已是 v0.3.1。
2. 将最终保存的 Room.py、object.py、源网格和材质复制到新的 `return_output/artifacts/room_batch_review_v010_<时间>_<随机ID>`。不改原结果，不从初始场景重建起步。
3. 重新编译保存的程序化物体和房间、复用神经网格。不会重新运行 ingest/reconstruct/TRELLIS/参考图生成/完整 author 阶段。重新编译 object.py 是验证代码对应模型，并不是重新生成家具。
4. 使用实际保存的贴图，不重新下载配方材质；缺失贴图明确报错。仅修改配方不会生成新像素，修复代理必须保存真实贴图文件。
5. 检查实例保留、静态支撑和现有几何验收，重开 Blender/GLB 导出。全部原始照片制作带帧号的缩略图页，独立选图会话为床头、床边柜、窗帘、床上织物、地面接触分别选至多两帧。再加六个覆盖扫描首尾的均匀全局视角，去重后最多 16 帧。不是固定帧号，也不是数学最优保证。不可见部位记为证据不足。
6. 从真实相机位姿重新渲染并配对原照片，独立评审当前版本。仍要求分数至少 8、没有未解决问题、所有对象已核实；不会以静态支撑通过代替视觉通过。
7. 如未通过，每批最多三条具体问题，优先支撑、灯光和大件外观，后做小配件。最多三批，每批修复会话 900 秒、45 次工具调用，要求在约 630 秒前保存收尾。编辑会话只依据上一轮证据修改源文件；不给它额外的 render/check_collisions MCP 工具，避免重复构建占用编辑预算。构建、碰撞/支撑检查和独立评审由监督脚本单独执行，检查不跳过，有各自预算，不从这 900 秒扣除。
8. 每批都保留源代码快照、构建、图片、评审和日志。即使修复超时，也先尝试对已保存代码重新构建和复评；随后停止继续编辑，保留结果。若代码无效则记录检查失败，上一批可查看候选仍保留。

这是基于固定版本 LiteReality 检查器增加的通用续跑调度，不是声称上游官方已经提供相同调度。没有写死房间几何、家具坐标或特定帧号；只有便捷启动脚本指定此次 room_004 的输入目录。

## 状态含义

- `accepted`：本轮保存版本通过完整检查和独立视觉验收；不等于动力学仿真认证。
- `quality_not_passed`：完整检查完成，质量或证据覆盖仍不满足要求。
- `repair_timeout`：修复到达墙钟时限，保存内容已尝试复评，质量仍未通过。
- `repair_step_limit`：修复到达工具步数上限，与时间超时分开。
- `check_failed`：构建、渲染、导出、评审网络/JSON 或其他验收执行失败，不能解释为低质量分数。
- `execution_error` / `interrupted`：运行错误或手动中断。

`result.json` 分别列 `quality` 和 `repair_termination`。若超时后保存版本恰好通过，状态可为 accepted，同时仍保留 repair_termination=timeout。若修复超时后连构建检查也失败，则主状态 check_failed，修复超时记录不会丢失。

## 返回什么

终端会打印进度、错误、最终状态、RESULT_DIR 和 RETURN_TAR。返回包统一在：

`/yinxin/projects/room/return_output/room_004_test_04_batch_review_<时间>_<随机ID>.tar.gz`

主要内容：

- `result.json`：各批质量和停止原因、总耗时、原源代码是否保持不变。
- `latest_candidate.json`：最近一次成功构建并重开的候选路径，可能仍未通过视觉验收。
- `scenes/<scene>/realism_authoring/rounds/round_XX/`：每轮源代码、room_preview/Room.portable.blend、Room.glb、validation.json、visual_review.json、compare/对照图。
- `evidence/selection.json`：针对性选图、理由和不可见项；all_capture/ 为所有照片缩略图。
- `sessions/` 和各轮 `review_session/`、各批 `session/`：实际 prompt、带时间的事件、结束原因、timing.json。
- `timings.jsonl`：构建、渲染、检查和模型会话的阶段耗时。

timing.json 的 observed_tool_seconds 是事件流能观测到的工具运行区间并集；unclassified_non_tool_seconds 混合模型、网络、排队和 CLI 开销，不能称为“纯思考时间”。CLI 未报告起止事件的工具不会被伪造时长。

返回包不带模型权重、原始 RGBD 扫描或 Codex 凭据。压缩包时间戳固定为 0，避免未来时间警告。由于每轮保留模型和材质，返回包可能较大，需留出数 GB 空间。
