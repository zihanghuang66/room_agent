# 单次批处理：视频 → 相机轨迹与稀疏点云

这是第一次实际重建任务，不是安装脚本。算法为 COLMAP 4.2.1：SIFT 特征、顺序匹配与几何验证、增量 SfM、CPU Bundle Adjustment。默认 SIFT 提取和匹配使用一张 GPU；不运行稠密重建、Mesh、家具分割或 UE5。

## 当前视频与完整执行命令

当前修复版：`v0.1.2`，保留 FFprobe 4.4 兼容修复，并统一把运行产物写入 `return_output/`。用户已确认视频为 `/yinxin/projects/room/data/raw/room_001/IMG_4220.MOV.zip`。将 `room-sparse-batch-v0.1.2.tar.gz` 上传到 `/yinxin/projects/room/scripts/` 后执行：

```bash
cd /yinxin/projects/room/scripts
tar -xzf room-sparse-batch-v0.1.2.tar.gz
/usr/bin/python3 /yinxin/projects/room/scripts/sparse-batch/run.py \
  --video /yinxin/projects/room/data/raw/room_001/IMG_4220.MOV.zip
```

如果上传的是解压后的源码文件夹，保持 `scripts/sparse-batch/` 结构，跳过 `tar` 一行即可。原 ZIP 保留，脚本只从 ZIP 读取一个视频，忽略 macOS 附加元数据；多个视频、加密 ZIP、不安全路径或符号链接会停止并报告，不猜选视频。

默认使用此前验证成功的环境：

```text
/yinxin/projects/room/.venvs/room_setup_20261030T073737Z_pb2ho14u/bin/python
```

该环境不在当前容器中时，脚本停止并说明原因。可用 `--python /实际已验证环境/bin/python` 指定其他环境；不会自动重装或猜选其他目录。

## 一次执行的步骤

1. 检查视频路径、磁盘空间、PyCOLMAP 版本与配置、当次 GPU 身份。
2. 必要时解压视频，记录输入校验值；读取时长、尺寸、编码、旋转及色彩信息。
3. 抽取视频前 60 秒，最多 120 帧，目标每秒 2 帧，长边不超过 1600 像素；生成抽帧清单和预览拼图。
4. 在一个明确的 CUDA 逻辑设备上运行 SIFT 特征提取，再做顺序匹配和几何验证；不自动切换 CPU 掩盖 GPU 错误。
5. 运行增量式 SfM 和 CPU BA，记录每个独立模型的注册帧数、点数、重投影误差分布、相机位姿与内参，导出完整模型和 PLY。
6. 打包结果与诊断信息到 `return_output/`，输出 `Return this archive:`。

单个外部步骤默认最多 30 分钟，超时停止并回传日志；没有无人值守自动重试。失败时保留此前产物，但再次运行会建立新目录，不自动断点续跑。终端每 30 秒提示当前步骤，详细进度在打印的日志路径中。

## GPU 与参数

学校平台按申请挂载 GPU，本脚本保留平台设置的设备可见范围，默认只使用其中 CUDA 逻辑编号 `0`，不固定为 3090，不选择“显存最空”的其他卡。若当次容器有多张获配 GPU，可用 `--gpu-index 1` 指定其中另一张；这是 CUDA 可见范围内编号，未必等于宿主 `nvidia-smi` 编号。报告记录实际选择的 UUID、型号和可见性变量。CPU 模式可显式传 `--device cpu`，其结果不能证明 GPU 运行成功。

常用可选参数：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--start` | 0 | 从第几秒开始 |
| `--seconds` | 60 | 最多处理的片段长度，上限 600 秒 |
| `--frames` | 120 | 抽帧上限，允许 6–300；过长片段会降低采样频率 |
| `--max-size` | 1600 | 最大图像边长，允许 320–2400 |
| `--threads` | 8 | CPU 线程配置，不根据宿主可见 CPU 数占满资源 |
| `--step-timeout` | 1800 | 每步骤最长秒数，上限 7200 |
| `--prepare-only` | 关闭 | 只解压、检查和抽帧，不进行重建，也不要求 PyCOLMAP/GPU |
| `--camera-mode` | single | 共享内参；只有明确需要时用 per-image 尝试每帧内参 |

初始数值只是控制首轮资源消耗的配置，不是质量保证。ZIP 中单个视频限制 20GiB，默认要求解压后文件系统仍留 5GiB；这是粗略空间保护，不代表已确认个人配额或完整任务的空间需求。

回传压缩包包含报告、预览和各步骤日志尾部（每份最多 256KiB），不包含原视频、全部抽帧、数据库或完整点云。你只需传回最后打印的压缩包。生成目录和压缩包使用唯一名称，不覆盖旧结果；tar/gzip 时间戳固定为 0，避免未来时间警告。

`sparse_completed_review_required` 表示流水线生成了稀疏模型，**不表示质量验收通过**。`prepared_only` 表示只做了视频预处理。`failed` 表示某一步失败，查看报告与日志再决定是否重跑。

## 结果解释

- 坐标尺度任意，未标定为米；不同模型可能是互不相连的重建，不能直接当作同一坐标系。
- 均匀抽帧不是模糊过滤或覆盖质量保证；首轮不自动删除疑似低质量帧，保留可追溯证据。
- 默认共享相机内参，适合固定镜头且无变焦的视频。切换镜头、变焦和电子防抖可能破坏该假设，需结合结果调整。
- 当前顺序匹配关闭词汇树回环检测，不下载模型；覆盖不足和长路径漂移可能影响结果。
- HDR 视频会标记警告，当前抽帧不做经标定的 HDR 色调映射；拼图颜色不作为材质保真验收。
- 稀疏点云不是房间表面模型。只有检查轨迹、注册覆盖和几何后，才进入 MVS 与网格化。

API 按 [COLMAP 官方 PyCOLMAP 说明](https://colmap.github.io/pycolmap/index.html)及 [4.2.1 特征提取接口](https://github.com/colmap/colmap/blob/4.2.1/src/pycolmap/pipeline/extract_features.cc)、[匹配接口](https://github.com/colmap/colmap/blob/4.2.1/src/pycolmap/pipeline/match_features.cc)、[SfM 接口](https://github.com/colmap/colmap/blob/4.2.1/src/pycolmap/pipeline/sfm.cc)核对。

本地已完成 7 项自动检查（包括真实 FFmpeg 抽帧及旧版 section 名兼容检查）以及 PyCOLMAP 4.2.1 的 CPU 合成视频全流程测试；测试最大模型注册了 24/24 帧，导出了 4545 个稀疏点。模型可能包含重叠子集，报告分别记录各模型和最大模型，不能直接合并坐标。此测试不证明真实房间精度，也不代替学校 CUDA 实测。

首份真实运行报告在 `video_probe` 阶段因 FFprobe 4.4 不接受 `stream_side_data` section 名而停止，尚未抽帧或重建。已改用旧版支持的 `stream_side_data_list` 父节点，保留旋转信息，无需升级 FFmpeg。依据 [FFmpeg n4.4.2 的 section 定义](https://github.com/FFmpeg/FFmpeg/blob/n4.4.2/fftools/ffprobe.c)。回归测试模拟该旧版错误后调用本地 FFprobe，验证视频读取、旋转信息与抽帧；不宣称已在学校二进制上复测。
