## 本次问题与修复

第 9 个图像生成会话 ChairCluster1 因 connection failed 没有生成 PNG，但 Codex 仍 exit=0、turn.completed。
旧适配器随后报文件不存在，掩盖了网络根因。前 8 张参考图已保存；尚未进入三维家具生成。

- PNG 和来源回执仍必须实际存在且通过校验；会话正常结束不等于生成成功。
- 明确输出网络、登录、额度、工具不可用、交付不完整、图片校验等错误类别与原始原因。
- 仅“没有交付图片且有网络失败证据”的情况自动重试，最多 3 次会话（首次 + 2 次），分别等待 15/30 秒。每个会话最多调用一次 imagegen。
- 默认总图像会话上限仍为 64，包含历史会话和重试；失败后停止其他排队任务。
- 登录、额度、工具不可用、图片不合法或来源不合法不会盲目重试。若同会话已留下本地原生图片但未完成交付，也不自动重新生成。
- 超时不一定意味着远端没生成；网络重试可能额外消耗额度，不能保证远端恰好执行一次。设置 ROOM_IMAGE_ATTEMPTS=1 可关闭自动重试。
- 已有图像通过输入证据 + prompt + 模型 + 输出 SHA256 核对后复用。椅子也走同样校验，并补齐 reference_status 等记录，避免后续验收误报。
- 椅子分组在图像生成前保存断点；相同证据和配置续跑复用分组。旧 v0.2.2 没保存分组断点，本次需要重新判断一次分组；若证据或分组变化，不会强行复用不匹配的椅子图。普通家具 7 张及匹配的椅子图可复用。

不能保证网络永不故障；本版解决错误被掩盖、短暂网络故障无恢复机制以及椅子续跑状态缺失。
没有降低几何或视觉验收条件。

## 续跑顺序和输出

重新检查当前容器环境 → 进入未完成 ingest，复用匹配的提取/裁图/参考图 → 补齐椅子和门窗参考图 → reconstruct → seed → author → publish → 导出文件重开检查。

不包含、安装或替换 Codex 运行时；使用既有 ROOM_CODEX/PATH、已登录会话和 GPU 环境。动态 GPU 分配仍遵守 CUDA_VISIBLE_DEVICES。

所有日志、诊断和返回 tar 在 `/yinxin/projects/room/return_output`。保留原 result/input 历史，增加 resume_*.json。
错误会打印终端；每次图像尝试有 imagegen/<时间_随机值>/failure.json、logs、request.json；总结果在 result.json。
普通异常会尝试打包 return_output/room_003_test_03_full_<时间>_<随机值>.tar.gz。
SIGKILL、容器回收、磁盘耗尽无法保证最后打包成功。

如果只想收集该续跑目录，不调用模型：
```bash

```
