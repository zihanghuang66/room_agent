1. 探测 GPU、编译器、基础工具与公开 HTTPS 端点。401/403 不代表模型可用。
2. 核验随包携带的官方源码，按 uv.lock 安装/同步基础环境；复用同版本环境与下载缓存。
3. 记录新扫描 SHA256，安全解包并定位扫描目录。服务器文件指纹不代表与本地原件独立比对。
4. 自动枚举 RGB-D/相机 JSON，检查缺失配对，完整读取所有匹配帧。
5. 用官方提取器解析 RoomPlan、RGB-D、相机参数与扫描几何。

7. 输出帧统计、深度有效比例、置信度统计、墙体/物体数量及最多 12 张照片的缩略图。

缩略图用于人工检查扫描覆盖，可能保留原始拍摄方向。深度有效率不代表真实精度。

## 要求与边界

Python 3.10–3.12，系统 pip 支持 --python；首次安装可访问 PyPI。
基础环境至少预留 4 GiB；原始扫描、展开副本及提取产物另外占空间。
当前安全解包限制为解压后不超过 2 GiB，超出会报告错误，不截断扫描。
扫描目录需含 frame_*.json、同编号 JPG/深度 PNG，以及 room.usdz 或 roomplan/room.usdz。
嵌套目录支持最多三层；不同格式会明确失败，再根据报告适配。
官方提取器要求同一扫描内帧分辨率一致，本包校验内参以防静默误缩放。

上游固定 commit 28ffe1fd4a1b03c93f1877a33a8bc9b806f72fe1，官方源码不修改。
源码 SHA256 b8f70258dda704a38df8091dd4f96604dd4b7a9ab14e296ef4962c84489773b1。
本包不安装 Blender、TRELLIS.2 或 GroundingDINO GPU 环境，也不占用 GPU 推理。
完整 ingest 会调用 Agent/模型，不能把本次离线提取当作完整 ingest 或房间重建成功。
本地已用旧扫描派生的 3 帧不同分辨率样本验证通用读取；新扫描只能由服务器实际验证。

## v0.2.1 修复说明

服务器报告 room_litereality_prepare_20261031T012845Z_2848f59c 显示基础 110 个包已安装，
但 uv pip check 报 Open3D 缺少 ipywidgets>=8.0.4，尚未开始扫描提取。
官方 Linux CPython 3.10 Open3D 0.19.0 wheel 的 METADATA 有此依赖，Mac wheel 没有，固定上游 uv.lock 也没有。

修复流程：先按原始锁文件同步，再记录全部已安装版本为约束，安装 linux-compatibility.txt 中固定版本与 SHA256 的补充包，最后运行完整依赖检查。
补充包以 ipywidgets==8.1.7 为入口，针对 Linux / Python 3.10 解析；包含完整传递依赖。
不修改上游源码或 uv.lock，不跳过依赖检查，不删除既有环境、缓存或扫描。
重复运行时 uv sync 可能移除补充项，脚本随后会从缓存补回。
--app-python 表示调用方提供已经完整安装的环境，会跳过安装和本次自动修复；服务器请使用默认启动命令。

本地验证：Linux 目标平台依赖解析、带哈希的 wheel 下载/安装到隔离目录、元数据依赖闭包检查。
这不是 Linux 原生运行验证；学校容器重跑后的 pip_check.log 和扫描提取结果才是最终依据。
